# Core: *Threadbare* -- Full Curriculum (English)

See sessions.md for the full session-by-session teaching content.

Extracted 4 August 2026 from the English source decks in Google Drive. Five milestones spanning 18 sessions, plus the learner playbook.

**Program shape:** a cohort course. Learners build a StoryQuest across five milestones; the deliverable is a playable prototype published from their own GitHub organization.

**Fidelity note and a real warning about coverage:** Milestones 4 and 5 and the Learner Playbook extracted richly -- the playbook in particular carries the full project board with per-task acceptance criteria for all five milestones, a roughly 100-term glossary, and the complete GitHub setup walkthrough. Milestones 1 through 3 are much thinner, because those decks are visually driven: most session slides carry only an activity title, with the instruction living in embedded visuals, videos, or linked worksheets that text extraction cannot reach. Treat the Milestone 1-3 sections as a reliable skeleton, not as complete teaching content. There is no scored rubric and no standalone code of conduct in any source; assessment is the acceptance-criteria checklists.

### Open Source

*Threadbare* is open source! This means that we are in front of a development model where software source code is made publicly available, allowing anyone to use, modify, and distribute it freely. And this implies:

- Code and assets are public and openly-licensed
- The game "lives" in Github, where all of this plus issues and pull requests are also visible and can be tracked
- When you contribute to *Threadbare*, your work lives on! Even after the program, you can keep working on your StoryQuest, propose another, or even contribute to other parts of the *Threadbare* game (either independently or in other programs, like More).

### Core: Learning Principles

**Everyone belongs.**
We celebrate inclusion and diversity within the game-making community.

**Play matters.**
We recognize creative play as fundamental to learning and living.

**Create for impact.**
We inspire game makers who create meaningful change in the world.

**Share often. Be open.**
We promote safe, collaborative spaces where game makers learn from one another.

**Reflect and refine.**
We value intentional reflection that helps us grow and evolve.

**Learning is not linear.**
We embrace flexibility and failing forward in an iterative design process.

### Core: Learner Outcomes

By the end of this program, you will:

- Understand key game design concepts
- Come up with ideas for a StoryQuest
- Create a prototype of a playable StoryQuest\*
- Plan a game design project
- Collaborate with others to build your game
- Consider the diverse needs of players
- Communicate your game idea\* to others

\*how you will be assessed

### Before we start

You'll need:

- A Discord account.
- The link to our server (you'll receive further instructions to join a group if you're in a specific program. If not, ask for help on our server!)
- Git downloaded & installed (according to the Operative System you use: Microsoft, Mac, Linux, Endless, etc.). Ask for help in our Discord if needed!
- A GitHub account.
- Godot's latest version downloaded & installed (this also has to do with your OS, so don't hesitate to ask for help on our server!) [Current latest version: 4.5]
- An Endless Studios Platform account.

### Endless Studios Platform: The Program + On-Ramps

To access Core: *Threadbare* you should:

1. Sign in with your username to the Platform.
2. Find the "I have a code" button to the left.
3. Click the button and put in the code\* that was shared with you.

This will be the final resting place for your prototype (although it will also be in GitHub).

In the Platform you can access the On-ramps: three mini-modules of specific content that you can use to practice.\*\* These are the Godot On-ramp, the Game Design On-ramp, and the Git On-ramp. To enter to any of them, use the same process shown above.

\*Send an email to learning@endlessaccess.org if you need an access code.
\*\*On-ramps are not mandatory and they are designed to be done as self-led modules.

## Extraction gaps and caveats

- **No code snippets.** Neither Milestone 4 nor Milestone 5 sessions contain any code. All technical work in these milestones is Git/GitHub workflow (branches, PRs, upstream submission) and Godot Inspector editing of `quest.tres`, which is described in the linked GitHub tutorials rather than in the decks.
- **No rubric with scored levels.** The program's assessment model is the per-item **Acceptance Criteria** checklists on the GitHub Project Board, reproduced in the playbook. There is no points-based or leveled rubric in these three sources.
- **No standalone code of conduct.** The closest learner-facing equivalents are the six **Learning Principles** ("Everyone belongs," etc.) and the Discord community forum links. No separate conduct policy document appears in the playbook.
- **Slide bodies are minimal by design.** Each activity slide typically shows only its title (and, in the corner, a duration). The instructional substance lives in the speaker notes, captured in sessions.md. The decks are also heavily illustrated; decorative art has been dropped.
- **Link URLs partly unrecoverable.** The decks' Resources lists name their targets in link text but the text export did not always carry the URL. URLs were recovered for the Project Board, the "Conduct playtesting sessions" and "Create Your Game Pitch Deck" issues, the Endless Studios platform, the Pitch Deck template, and the three pitch-related videos. Resources listed without a URL above (Playtesting Feedback Form template, "How to create a web page for your video game on the Endless Platform" video, Gather and Reflect on Player Feedback, Refine Your Game, Publish your StoryQuest, Submit a StoryQuest Upstream, Present your StoryQuest, Game Design Awards folder, Post-survey) are named exactly as they appear on the slides.
- **Verbatim source errors preserved.** The following are typos/slips in the originals, kept as-is for fidelity: "if team makes a StoryQuest"; "A fresh perspective catch things"; "game makers with get familiar"; "comments from playesters"; "In their breakout room or physical space)" (unbalanced parenthesis); "(even if that means letting some details go."
